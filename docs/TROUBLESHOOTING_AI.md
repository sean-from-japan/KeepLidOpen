# 自分のMacで動かないとき・AIを使って調べるとき

KeepLidOpenは、MacBook Air（M5）・macOS 26.6.2・Dell S2725DSMで検証しました。別の機種、macOS、ドック、DisplayLinkなどでは、インストールや画面の切り替えが違う結果になる可能性があります。このページは、自分の環境で原因を調べ、必要ならAIと一緒にローカルで修正するための手順です。修正できることや安全に動作することを保証するものではありません。

## 画面が真っ暗なら先に復旧する

1. 外部モニターをつなぎ直す。
2. MacBookのふたを一度閉じて開ける。
3. ログアウトしてログインし直す。
4. 再起動する。

画面が見えないまま新しいコマンドを推測で実行しないでください。復旧後、使い続けない場合は、クローンしたフォルダから `scripts/uninstall.sh` を実行できます。

## AIに渡す情報を集める

まず症状を「ビルド・インストールが失敗する」「インストールできるが切り替わらない」「内蔵画面を戻せない」「スリープ後だけ変わる」などに分けます。Macの機種、macOSのバージョン、外部モニター、接続方法（直結・ドック・DisplayLinkなど）、再現手順と復旧できた方法も控えてください。

以下は画面の切り替えを実行しない読み取りコマンドです。失敗したコマンドの**全文とエラー**も控えます。

```sh
sw_vers -productVersion
uname -m
swift --version
xcode-select -p
tail -n 80 "$HOME/Library/Logs/KeepLidOpen.log"
```

ログがない場合は「ログなし」と伝えてください。公開する前に、ログやエラーに自分の名前、ユーザー名、ホームフォルダ、機器名などが含まれていないか確認してください。AIサービスに貼る場合も同様です。症状の前後の行だけで十分です。

## AIに渡すプロンプト

下の文をコピーし、角括弧の項目とログを埋めて、**KeepLidOpenのリポジトリを開いたコーディングAI**に渡してください。AIがリポジトリにアクセスできない場合は、README、`docs/FINDINGS.md`、関連する `Sources/` と `Tests/` のファイルを渡します。エラーだけから修正を推測させないためです。

```text
KeepLidOpenが私のMacで動きません。リポジトリの実装とdocs/FINDINGS.mdを読み、手元の事実から原因を調べ、必要なら最小限のローカル修正をしてください。

機種: [例: MacBook Air M5]
macOS: [sw_vers -productVersion の結果]
Swift・開発ツール: [swift --version と xcode-select -p の結果]
モニターと接続: [型番、直結/ドック/DisplayLinkなど]
症状: [何をすると、期待と実際がどう違うか]
再現手順: [番号付きで]
復旧できた方法: [つなぎ直し、ふたの開閉、ログアウトなど。未確認ならその旨]
失敗したコマンドとエラー: [全文。秘密情報は伏せる]
関連するログ: [症状の前後だけ。秘密情報は伏せる。無ければ「なし」]

進め方:
1. 最初にgit statusを確認し、既存の変更を保存・上書きしない。インストール失敗と実行時の不具合を分ける。
2. 関連するSources/、Tests/、scripts/、docs/FINDINGS.mdとログを読み、観測事実・仮説・未確認事項を分けて説明する。不足する情報があれば先に聞く。
3. 画面ID、vendor/model、macOS内部APIの挙動を推測で決め打ちしない。過去の実測値を、私の環境の値として扱わない。
4. ソース修正が必要なら、最小の差分にし、対応する回帰テストを追加してscripts/test.shを実行する。ビルド・インストールの問題なら、まず表示切り替えを伴わない範囲で検証する。
5. 内蔵画面をオフにする実機テスト、scripts/install.shの再実行、常駐設定の変更を始める前に、復旧手順と何が起こるかを説明し、私の明示的な了承を待つ。sudo、nvramの変更、恒久的な画面オフ設定は提案だけで実行しない。
6. 最後に、確認できた原因、変更したファイル、テスト結果、まだ実機で未確認の点、元に戻す手順を示す。成功を保証しない。commit・push・公開は私が依頼するまでしない。
```

改善が見つかった場合は、[不具合報告](https://github.com/sean-from-japan/KeepLidOpen/issues/new/choose)に環境、再現手順、原因と修正結果を共有してもらえると、同じ機種で困る人の助けになります。ソース変更がある場合はPRも歓迎します。
